# v4.13.0 — Desktop activity same-day reorder

## Summary

**v4.13.0** adds explicit same-Day Activity reordering to the Desktop developer preview:

- Move an Activity up or down within the selected Day
- Use keyboard-accessible native controls with clear first, last, and one-item boundary states
- Reject stale placement requests by validating the full rendered Activity-ID order
- Apply ordering changes atomically in the Core service
- Refresh the selected Day from SQLite while preserving Activity and Inspector context

The user-facing Desktop vocabulary remains **Activity**. The internal domain, Core API, and storage model continue to use **Itinerary**.

## Desktop Activity reorder

- Adds explicit Move up and Move down actions beside each timeline Activity
- Disables Move up for the first Activity, Move down for the last Activity, and both actions for a one-item Day
- Keeps native button keyboard behavior and restores focus after a successful DB-backed refresh
- Preserves the selected Activity, an open Inspector, and its unsaved draft during same-Day reorder
- Announces successful movement through a polite status message
- Prevents duplicate submissions and ignores stale completions after Trip, Day, Settings, New Trip, or database context changes

## Core ordering boundary

- Adds a narrow public same-Day Itinerary reorder service
- Revalidates the exact expected Activity order inside a single transaction before writing
- Reuses distinct sparse ordering slots when possible
- Performs checked normalization only when duplicate slots cannot express the requested canonical visible order
- Returns structured target-not-found, invalid-placement, conflict, and storage errors
- Preserves ownership, content fields, child associations, and every field other than `sort_order` and `updated_at`

## Readback and responsive behavior

- Refreshes only the selected Day timeline from SQLite after a successful reorder
- Does not optimistically reorder the frontend array
- Keeps timeline controls usable at the 1120×720 default size and the 720×480 minimum smoke size
- Keeps the existing Trip Workspace and viewport-constrained app shell unchanged

## Compatibility and packaging

- No database schema or migration changes
- No Travel Ledger export/import format changes
- No public CLI argument, output, or behavior changes
- Cross-Day move, drag-and-drop, and Undo are not included
- Desktop remains a **source-only developer preview** with bundling disabled (`bundle.active = false`)
- GitHub Release assets remain the CLI archives for Linux amd64, macOS arm64, and Windows amd64; no Desktop installer is included
